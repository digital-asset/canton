# External Signing

This folder contains example scripts to demonstrate how to sign daml and topology transactions using external keys.
Refer to the [documentation](https://docs.canton.network/appdev/deep-dives/external-signing) for more information.

## Prerequisites

- Bash-compatible terminal
- curl (https://github.com/curl/curl)
- jq (https://github.com/jqlang/jq)
- openssl (https://www.openssl.org/)
- optional
  - grpcurl (https://github.com/fullstorydev/grpcurl)
  - python3 (https://www.python.org/)
  - venv (https://docs.python.org/3/library/venv.html)
  - buf (https://buf.build/docs/)
  - xxd (https://linux.die.net/man/1/xxd)

## Scenarios
- create and onboard two parties using external keys to sign transactions
  - both single-hosted and multi-hosted party
- create and archive a Ping contract with external signing

## Running

### Preparation
- build canton: `sbt compile`
- build the release bundle: `sbt bundle`
- navigate to the release dir: `cd <code_repo_root>/community/app/target/release/canton`

### Running the onboarding example
Open two terminal windows in the above dir.

- first window
    - run `./bin/canton -c examples/08-interactive-submission/interactive-submission.conf --bootstrap examples/08-interactive-submission/bootstrap.canton`
        - starts Canton in interactive mode, bootstraps 3 participants and synchronizer (sequencer and mediator)
- second window
    - run `./examples/08-interactive-submission/external_party_onboarding.sh`
        - Run the scenario steps to allocate a new party on one participant node.
        - Create a private key using openssl for the external party.
        - Determine the synchronizer-id available.
        - Create a set of topology transactions to define a new external party.
          - Generated by calling the convenience Ledger API endpoint: `/v2/parties/external/generate-topology`.
        - Sign the topology transactions.
        - Upload the signed topology transactions to the Ledger API.
    - exit Canton and start it again in the first window
    - run `./examples/08-interactive-submission/external_party_onboarding.sh --multi-hosted`
        - Run the scenario steps to allocate a new party on two participant nodes.

## Further steps
### Multi-hosted party onboarding in Canton console
- refer to https://docs.canton.network/appdev/deep-dives/external-signing-onboarding
### Submitting externally signed Daml transactions
- refer to https://docs.canton.network/appdev/deep-dives/external-signing-transactions
- prepare the environment
  - start Canton: `../../bin/canton -c examples/08-interactive-submission/interactive-submission.conf --bootstrap examples/08-interactive-submission/bootstrap.canton`
  - set up Python virtual environment
    ```bash
       python -m venv .venv
       source .venv/bin/activate
       pip install -r requirements.txt
    ```
  - execute `./setup.sh` to generate Python bindings for the Ledger gRPC API
- run the example: `python interactive_submission.py run-demo`
### Submitting externally signed topology transactions
- refer to https://docs.canton.network/appdev/deep-dives/external-signing-topology
- prepare the environment
  - run the previous scenario
  - find the synchronizer id in the Canton console: `health.status`
  - change `default_admin_port` in `interactive_toppology_update.py` to 4002
- run the scenario in Bash: `./interactive_topology_example.sh localhost:4002 <synchronizer-id>`
- run the scenario in Python: `python interactive_topology_example.py --synchronizer-id <synchronizer_id> run-demo`
